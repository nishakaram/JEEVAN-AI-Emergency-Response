# JEEVAN API Reference

Base URL (local dev): `http://localhost:8000`

Interactive docs (auto-generated by FastAPI, always up to date): `http://localhost:8000/docs`

All responses are JSON. All emergency/responder data returned is
demonstration data — see the disclaimers in the main README.

---

## Emergencies

### `POST /api/emergencies/analyze`
Runs AI classification on raw text **without** creating an emergency record.

**Request body**
```json
{ "description_text": "There has been an accident, my father is unconscious and bleeding." }
```

**Response**
```json
{
  "emergency_type": "Road Accident",
  "severity": "Critical",
  "summary": "Road Accident reported — indicators: unconscious, bleeding, accident.",
  "assistance_required": "Immediate medical assistance",
  "indicators": ["unconscious", "bleeding", "accident"]
}
```

---

### `POST /api/emergencies`
Creates a new emergency. This is the main endpoint the SOS flow calls.
Runs, in order: save → log `emergency_request_received` + `location_obtained`
events → AI classify → log `ai_assessment_completed` → run responder
matching → log `responder_identified` + `responder_assigned` (or
`no_responder_available`) → simulate contact notification → log
`emergency_contact_notified` per contact (or `no_contacts_notified`).

**Request body**
```json
{
  "description_text": "There has been an accident...",
  "latitude": 26.9124,
  "longitude": 75.7873,
  "location_label": "Jaipur (Demo Location)",
  "user_id": 1
}
```
`location_label` and `user_id` are optional.

**Response**: full `Emergency` object (see schema below), including
`assigned_responder` (nested) and `events` (the full timeline so far).

---

### `GET /api/emergencies`
Lists all emergencies, most recent first. Used by the dashboard.

### `GET /api/emergencies/{id}`
Returns one emergency with its full details and event timeline.
`404` if not found.

### `POST /api/emergencies/{id}/assign`
Manually (re)assigns a responder.
- Query param `responder_id` (optional, integer): assign this specific
  responder.
- If omitted: re-runs the matching algorithm using the emergency's
  current AI-assessed severity and assigns the top match.
- `404` if the emergency or given responder doesn't exist, or if no
  responders are available at all.

### `PATCH /api/emergencies/{id}/status`
Updates an emergency's status. Used by the responder/admin dashboard.

**Request body**
```json
{ "status": "EnRoute" }
```
Valid values: `Created`, `Assessed`, `ResponderAssigned`, `EnRoute`, `Resolved`.
`400` on an invalid status, `404` if the emergency doesn't exist.

## Responders

### `GET /api/responders`
Lists every responder in the demo database, unranked.

### `GET /api/responders/nearby`
Returns every responder **ranked best-match-first** for a location and severity.

**Query params:** `lat` (required), `lng` (required), `severity`
(optional, default `Moderate`; one of `Low`/`Moderate`/`Critical`)

**Response** (one entry per responder):
```json
{
  "responder": { "id": 1, "name": "Jaipur City Ambulance 1", "type": "Ambulance", ... },
  "distance_km": 2.1,
  "eta_minutes": 2.8,
  "distance_factor": 33.7,
  "availability_factor": 30,
  "capability_factor": 15,
  "severity_compatibility_factor": 15,
  "total_score": 93.7
}
```
See `docs/ARCHITECTURE.md` for how the score is computed.

## Users & Emergency Contacts

### `POST /api/users`
Creates a demo user profile (no authentication in this prototype).

**Request body**
```json
{ "name": "Ramesh Kumar", "phone": "9876543210", "blood_group": "O+", "medical_notes": "Diabetic" }
```
`blood_group` and `medical_notes` are optional.

### `GET /api/users/{id}`
Returns a user with their saved emergency contacts. `404` if not found.

### `POST /api/users/{id}/contacts`
Adds an emergency contact to a user.

**Request body**
```json
{ "name": "Priya Kumar", "phone": "9123456780", "relationship_type": "Daughter" }
```

## Core Schemas (simplified)

**Emergency**: `id, description_text, latitude, longitude, location_label,
emergency_type, severity, ai_summary, assistance_required, indicators
(JSON string), assigned_responder_id, assigned_responder (nested
Responder), status, created_at, events (list of EmergencyEvent)`

**Responder**: `id, name, type, latitude, longitude, availability,
capabilities, contact, estimated_speed`

**EmergencyEvent**: `id, event_type, description, timestamp`

**User**: `id, name, phone, blood_group, medical_notes, created_at, contacts`
